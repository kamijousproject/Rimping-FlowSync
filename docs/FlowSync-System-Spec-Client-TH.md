# เอกสารสรุประบบ FlowSync สำหรับส่งมอบลูกค้า

วันที่จัดทำ: 18/05/2026

## 1. วัตถุประสงค์ระบบ
FlowSync เป็นระบบหลังบ้านสำหรับบริหารการขายแบบเครดิต ตั้งแต่การจัดการลูกค้า การออกใบสั่งซื้อ การติดตามการชำระเงิน การออกเอกสารทางการเงิน และการแจ้งเตือนอัตโนมัติ เพื่อให้ทีมงานควบคุมยอดค้างและความเสี่ยงด้านเครดิตได้อย่างเป็นระบบ

## 2. ขอบเขตการใช้งาน
- ใช้งานภายในองค์กร (Back-office) สำหรับพนักงานที่ได้รับสิทธิ์
- รองรับบทบาทผู้ใช้หลัก: Admin และ Super Admin
- รองรับกระบวนการตั้งแต่รับคำสั่งซื้อจนปิดยอดชำระ
- มีระบบแจ้งเตือนอัตโนมัติสำหรับรายการเกินกำหนดชำระ

## 3. บทบาทผู้ใช้งานและสิทธิ์
### 3.1 Admin
- เข้าดูข้อมูลหลักของระบบได้ตามสิทธิ์ที่กำหนด
- ดำเนินงานเอกสารขาย เครดิต และการติดตามชำระ
- ไม่สามารถจัดการข้อมูลสำคัญที่สงวนสิทธิ์ไว้สำหรับ Super Admin

### 3.2 Super Admin
- ทำได้ทุกอย่างเหมือน Admin
- สร้าง/แก้ไข/ลบลูกค้า และบริหารวงเงิน
- บริหารผู้ใช้งาน และมอบสิทธิ์ชั่วคราว

## 4. โมดูลหลักของระบบ
### 4.1 Dashboard
- สรุปยอดค้างชำระ สถานะเอกสาร และรายการที่เกินกำหนด

### 4.2 Customer Management
- ค้นหา ดูรายละเอียด และติดตามประวัติลูกค้า
- สร้าง แก้ไข ลบลูกค้า (ตามสิทธิ์)
- จัดการวงเงินเครดิตถาวรและชั่วคราว พร้อมขั้นตอนอนุมัติ
- แนบ/ลบไฟล์เอกสารลูกค้า
- ดูประวัติการแก้ไขข้อมูลลูกค้า

### 4.3 PO Management
- สร้างใบสั่งซื้อใหม่ พร้อมตรวจวงเงินก่อนบันทึก
- ติดตามสถานะงานตั้งแต่เริ่มต้นจนจบกระบวนการ
- แก้ไขใบสั่งซื้อได้ตามเงื่อนไข
- แนบเอกสารเซ็นและออกเลขเอกสารภาษี
- รองรับการรับชำระหลายงวด และจัดการกรณีชำระเกิน
- รองรับการสร้าง/แก้ไข/ยกเลิกใบลดหนี้

### 4.4 Billing Notes
- สร้างและติดตามใบวางบิลของลูกค้า
- เปิดดูและพิมพ์เอกสารเพื่อใช้งานภาคธุรกิจ

### 4.5 Invoice Management
- แสดงรายการใบแจ้งหนี้ พร้อมตัวกรองหลายเงื่อนไข
- เปิดดูรายละเอียดและประวัติการใช้งานเอกสาร

### 4.6 Receipt Management
- ดูรายการเอกสารรับชำระ
- เปิดเอกสารเพื่อพิมพ์หรือดาวน์โหลด

### 4.7 User Management
- สร้าง/แก้ไข/ลบผู้ใช้งาน (ตามสิทธิ์)
- กำหนดสิทธิ์การใช้งานและสิทธิ์ชั่วคราว

### 4.8 Notification & Cron Services
- แจ้งเตือนผ่าน LINE เมื่อเกิดเหตุสำคัญ
- ตรวจสอบรายการค้างชำระอัตโนมัติแบบตามรอบเวลา

## 5. ขั้นตอนการทำงานหลัก End-to-End
1. ผู้ใช้เข้าสู่ระบบและตรวจสอบภาพรวมจาก Dashboard
2. เลือก/สร้างลูกค้า และตรวจสอบวงเงินก่อนทำรายการ
3. สร้างใบสั่งซื้อและติดตามสถานะจนงานส่งมอบเสร็จสิ้น
4. ออกเอกสารทางการเงินที่เกี่ยวข้อง (ใบวางบิล/ใบแจ้งหนี้/ใบเสร็จ)
5. บันทึกการชำระเงิน ตรวจยอดคงเหลือ และปิดยอดเมื่อชำระครบ
6. ระบบทำงานแจ้งเตือนอัตโนมัติสำหรับรายการที่เกินกำหนด

## 6. กฎธุรกิจสำคัญ
- ก่อนสร้างใบสั่งซื้อ ระบบต้องตรวจวงเงินเครดิต
- การจัดการข้อมูลลูกค้าและผู้ใช้สำคัญต้องอิงตามสิทธิ์
- รองรับการชำระบางส่วนและหลายครั้งต่อใบสั่งซื้อ
- รองรับการจัดการยอดชำระเกิน: คืนเงินหรือเก็บเป็นเครดิต
- การเปลี่ยนแปลงข้อมูลสำคัญต้องมีประวัติการแก้ไข

## 7. ข้อมูลและเอกสารที่ระบบจัดเก็บ
- ข้อมูลลูกค้า วงเงินเครดิต และเงื่อนไขเครดิต
- ข้อมูลใบสั่งซื้อ รายการสินค้า สถานะเอกสาร
- ข้อมูลการชำระเงิน และไฟล์แนบหลักฐาน
- ข้อมูลใบวางบิล ใบแจ้งหนี้ ใบเสร็จ และใบลดหนี้
- ประวัติการใช้งานและประวัติการแก้ไขสำคัญ

## 8. ข้อกำหนดระบบและสภาพแวดล้อม
### 8.1 เทคโนโลยีหลัก
- Frontend/Backend: Next.js + TypeScript
- Database: MySQL
- Authentication: Session ด้วย cookie ที่ปลอดภัย
- Notification: LINE Messaging API

### 8.2 ตัวแปรแวดล้อมสำคัญ
- ฐานข้อมูล: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`
- ความปลอดภัย: `JWT_SECRET`, `CRON_SECRET`
- การอัปโหลดไฟล์: `UPLOAD_DIR`
- การแจ้งเตือน: `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_ADMIN_USER_ID`, `LINE_USE_BROADCAST`
- URL ระบบ: `NEXT_PUBLIC_BASE_URL`

## 9. ขั้นตอนการ Deploy
### 9.1 เตรียมเครื่องและซอฟต์แวร์
1. ติดตั้ง Node.js และ npm เวอร์ชันที่รองรับ
2. ติดตั้งและเตรียม MySQL
3. เตรียมโดเมน/เซิร์ฟเวอร์ และ SSL สำหรับ production

### 9.2 เตรียมโค้ดและ dependency
1. ดึง source code เวอร์ชันที่ต้องการ deploy
2. ติดตั้ง dependency ด้วยคำสั่ง `npm install`

### 9.3 ตั้งค่า Environment Variables
1. สร้างไฟล์ `.env.local` ตามเอกสาร `docs/ENVIRONMENT_VARIABLES.md`
2. ตั้งค่าการเชื่อมต่อฐานข้อมูลให้ถูกต้อง
3. ตั้งค่า secret และ LINE notification ให้ครบ

### 9.4 เตรียมฐานข้อมูล
1. สร้างฐานข้อมูลตาม schema ของโครงการ
2. ตรวจสอบบัญชีผู้ใช้ฐานข้อมูลและสิทธิ์การเข้าถึง
3. นำเข้าข้อมูลตั้งต้นตามแผนงาน ถ้าต้องการ

### 9.5 Build และเริ่มระบบ
1. ทดสอบในโหมดพัฒนา: `npm run dev`
2. สร้าง build สำหรับ production: `npm run build`
3. เริ่มระบบ production: `npm run start`

### 9.6 ตั้งค่า Reverse Proxy และโดเมน
1. เชื่อมต่อโดเมนมายังแอปพลิเคชัน
2. ตั้งค่า HTTPS/SSL
3. กำหนดเส้นทางให้เข้าถึงระบบได้จาก URL จริง

### 9.7 ตั้งค่า Cron Job อัตโนมัติ
1. ตั้งเวลาเรียกงานตรวจสอบรายการเกินกำหนดชำระ
2. กำหนด header สำหรับความปลอดภัยของงานอัตโนมัติ
3. ตรวจสอบ log ว่างานทำงานครบตามรอบ

### 9.8 ทดสอบหลัง Deploy
1. ทดสอบ login/logout และสิทธิ์ผู้ใช้
2. ทดสอบสร้างลูกค้า สร้าง PO และบันทึกชำระเงิน
3. ทดสอบเอกสารใบวางบิล/ใบแจ้งหนี้/ใบเสร็จ
4. ทดสอบการแจ้งเตือน LINE และ cron

### 9.9 แผนสำรองและดูแลต่อเนื่อง
1. จัดทำแผนสำรองฐานข้อมูลรายวัน
2. เฝ้าระวัง log และการใช้ทรัพยากรเซิร์ฟเวอร์
3. กำหนดรอบอัปเดตระบบและทดสอบก่อนปล่อยจริง

## 10. ขอบเขตการส่งมอบ
- ระบบงานตามฟังก์ชันที่ระบุในเอกสารนี้
- เอกสารประกอบการติดตั้งและการใช้งาน
- ไฟล์ตั้งค่าที่จำเป็นสำหรับการ deploy
- คู่มือการใช้งานสำหรับผู้ปฏิบัติงาน

## 11. สมมติฐานและข้อควรทราบ
- ผู้ใช้งานต้องได้รับบัญชีและสิทธิ์ก่อนเข้าใช้งาน
- การทำงานของการแจ้งเตือนขึ้นกับการตั้งค่า LINE และเครือข่าย
- ควรมีการสำรองข้อมูลก่อนอัปเดตระบบทุกครั้ง
